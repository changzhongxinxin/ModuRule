# Telegram 双向私信客服机器人 · 部署文档

> 单文件 Cloudflare Worker 项目（源码：`Tg机器人.js`，部署时重命名为 `worker.js`）。
> 用户私聊机器人 → 消息转入管理员群组的独立话题；管理员在话题里回复 → 自动转达用户。
> 存储：Cloudflare D1（3 张表，自动建表）｜风控：Cloudflare Workers AI + 关键词双层拦截。

---

## 一、功能总览

### 消息转发
- **双向转发**：用户私聊 → 群组话题；管理员话题内回复 → 转达用户。支持文本/图片/视频/文件/音频/动图
- **编辑同步**：任何一方编辑已发消息（含给媒体补写/修改说明），对方副本**原地更新**（映射保留 7 天，格式同步保留）；用户编辑过的消息在话题里带常驻 🦄 标记；编辑内容同样过风控
- **相册聚合**：等待 3 秒聚合发送（多实例并发安全）；每条图片的独立说明均保留；发送失败自动重试（最多 3 次）
- **话题自愈**：话题被删自动发现 → 重建并要求用户重新验证；数据库锁保证并发只建一个话题
- **临时消息自动撤回**：欢迎语 60 秒、验证消息 300 秒、各类提示 120 秒、cleanup 报告 120 秒；拦截/封禁/关闭/失败提示和管理结果不撤回。秒数用 `AUTO_DELETE_*` 调整（`0` 关闭）；由后台每分钟清扫执行，配置 Cron 触发器可保证静默期照常清理

### 安全与风控
- **Turnstile 人机验证**：新用户首次发消息需点击链接完成验证（链接 5 分钟有效，通过后默认 7 天）。验证期间继续发消息会自动重发验证链接（受频控保护，不会卡死）；频控超限的消息不丢弃，验证通过后自动补达
- **双层垃圾信息拦截**：
  1. 关键词硬拦截（内置默认词库：日结/刷单/加微信等，支持正则自定义）
  2. Workers AI 判定（文本结合双方最近 12 条对话情景，只拦截广告营销（含诈骗刷单），辱骂/人身攻击/威胁/性骚扰/持续骚扰等非广告内容一律放行；无 caption 的纯图片可选视觉审核）
- **拦截处理**：消息不转发、用户收到提示；管理端不通知（仅日志留痕）。拦截计数 30 天窗口累计，达阈值（默认 5 次）自动封禁
- **防绕过**：验证期间的消息先进暂存——关键词层入队时拦截（不耗 AI 额度），AI 层在补发前按最新文本复查；补发中途触发封禁立即终止
- AI 白名单：白名单用户（`/aiwhitelist` 或卡片按钮开关）跳过 AI 检测；AI 调用失败自动放行，不影响正常聊天
- 限速：用户消息 45 条/分钟、验证请求 3 次/5 分钟

### 管理能力
- **资料卡（实时状态面板）**：新用户自动建话题并发送资料卡（昵称/用户名/ID/首次连接时间/话题ID/验证/对话/封禁状态/AI拦截次数）并**置顶在本话题**，所有管理操作点卡片按钮**就地执行并刷新卡片**，非管理员点击无效
- **卡片/面板按钮**：绝大多数管理操作点按钮就地完成并刷新（详见第五节说明）
- **🧹 清理失效话题**：管理面板按钮一键扫描并清理"话题已被手动删除"的失效用户（含消息记录）
- `/health` 健康检查（不带密钥=只读基础状态）；管理模式 `?key=<HEALTH_KEY>` 执行 Webhook 注册/同步（`&rotate=1` 轮换防伪密钥）；`&aitest=<文本>` 用自定义文本现场实测一次 AI 判定

## 二、前置准备

| # | 准备项 | 说明 |
|---|---|---|
| 1 | 创建机器人 | Telegram 找 **@BotFather** → `/newbot` → 记下 **BOT_TOKEN** |
| 2 | 关闭隐私模式 | BotFather → `/mybots` → 你的 bot → Bot Settings → **Privacy Mode → Disable**（否则收不到群内管理员回复） |
| 3 | 创建超级群组 | 新建群组 → 开启"话题（Topics）"功能 → 把机器人拉进去 → **设为管理员**，权限至少勾选「管理话题」和「置顶消息」（`/menu` 置顶面板需要） |
| 4 | 获取群组 ID | 使用第三方客户端打开群组看地址栏 `#-100xxxx` 部分 → 即 **SUPERGROUP_ID**（`-100` 开头） |
| 5 | 创建 Turnstile | Cloudflare 控制台 → **Turnstile** → Add Site → 域名填你的 `xxx.workers.dev` → 得到 **Site Key** 和 **Secret Key** |
| 6 | 创建 D1 数据库 | Cloudflare 控制台 → **存储和数据库 → D1** → 创建（名字随意，如 `tg-bot`）；或命令行 `npx wrangler d1 create tg-bot` |

## 三、需要的环境变量与绑定

### 绑定（在 Worker 的「设置 → 绑定/ Bindings」中添加）

| 名称 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `DB` | D1 数据库 | ✅ | 选第二步创建的数据库；**数据表首次访问自动创建，无需执行 SQL** |
| `AI` | Workers AI | 建议绑定 | AI 垃圾信息风控用；不绑定时 AI 层自动跳过，关键词层仍生效 |

### 环境变量（在 Worker 的「设置 → 变量和机密 / Variables」中添加）

**必填：**

| 变量 | 示例值 | 说明 |
|---|---|---|
| `BOT_TOKEN` | `123456:AAxxxx...` | 机器人 Token（@BotFather 获取） |
| `SUPERGROUP_ID` | `-1001234567890` | 超级群组 ID，必须 `-100` 开头 |
| `TURNSTILE_SITE_KEY` | `0x4AAA...` | Turnstile 前端 Site Key |
| `TURNSTILE_SECRET_KEY` | `0x4BBB...` | Turnstile 后端 Secret Key |

**可选：**

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ADMIN_IDS` | 无 | 管理员白名单（逗号分隔的用户 ID），**与群管理员身份取并集**（两者任一即视为管理员）；不配置则仅群组的创建者/管理员算管理员 |
| `HEALTH_KEY` | 无 | **强烈建议配置**。未配置：管理操作一律不可用（仅首次部署允许无密钥引导注册）。配置后：不带密钥=只读状态，带 `?key=<HEALTH_KEY>`=管理模式（Webhook 注册/同步、刷新域名；`&rotate=1` 轮换防伪密钥；`&aitest=` 实测 AI）。仅用于 /health 鉴权，不参与 Telegram 推送校验 |
| `AI_SPAM_CHECK` | `true` | 设为 `false` 关闭 AI 判定（关键词层不受影响） |
| `AI_SPAM_THRESHOLD` | `5` | 拦截累计几次后自动封禁 |
| `AI_MODEL` | `@cf/zai-org/glm-4.7-flash` | 文本审核模型，中文判定更强；模型被官方下线时报 5028 错误，到[模型目录](https://developers.cloudflare.com/workers-ai/models/)换现役模型即可 |
| `AI_IMAGE_CHECK` | `true` | 无 caption 的纯图片是否启用视觉审核；设为 `false` 关闭（图片仍可转发） |
| `AI_IMAGE_MODEL` | `@cf/meta/llama-4-scout-17b-16e-instruct` | 图片审核视觉模型；图片审核按像素消耗 AI 额度，免费额度有限 |
| `BLOCK_KEYWORDS` | 内置默认词库 | 屏蔽关键词正则（`日结\|刷单\|加微\|引流`），每行一条，`//` 为注释；设为空字符串 `""` 关闭 |
| `AUTO_DELETE_WELCOME` | `60` | 欢迎语自动撤回秒数，设 `0` 关闭 |
| `AUTO_DELETE_VERIFY` | `300` | 验证消息自动撤回秒数（默认与验证链接 5 分钟有效期一致），设 `0` 关闭 |
| `AUTO_DELETE_NOTICE` | `120` | 临时提示自动撤回秒数（验证成功/频控//info 卡片/用法提示等）；广告拦截、关闭对话、转发失败和正常管理结果不自动撤回，设 `0` 关闭 |
| `AUTO_DELETE_CLEANUP` | `120` | cleanup 过程/报告消息自动撤回秒数，设 `0` 关闭 |
| `API_BASE` | `https://api.telegram.org` | Telegram API 地址，一般不用改 |
| `AI_DEBUG_LOG` | 关闭 | 设为 `true` 把 AI 原始响应写入日志（排查判定不准用；Workers Logs 按条数计量，平时保持关闭） |

> **Webhook 防伪密钥无需配置**：代码自动生成存库并经 setWebhook 交给 Telegram，入口据此拒绝伪造更新；管理模式可 `&rotate=1` 轮换。密钥落库前入口拒绝所有 POST（正常流程下落库先于首条消息，不受影响）。
>
> **可靠性**：处理出现瞬时故障时返回 503，Telegram 会自动重试该更新，避免消息丢失。

## 四、部署方式

### 方式 A：Cloudflare 控制台（推荐新手）

1. Workers 和 Pages → **创建 Worker**（名字随意，如 `tg`）
2. 编辑代码 → 把 `Tg机器人.js` 的全部内容粘贴进去 → 部署
3. 设置 → **绑定** → 添加：
   - D1 数据库 → 变量名称 `DB` → 选择你的数据库
   - Workers AI → 变量名称 `AI`
4. 设置 → **变量和机密** → 按上表添加所有必填变量
5. **配置管理密钥 + 激活**：添加 `HEALTH_KEY` 变量 → 部署后访问一次 `https://<你的域名>/health`
   → Telegram 侧尚未注册时自动完成首次注册；Worker 域名自动记录，无需配置。此后管理模式访问带 `?key=<HEALTH_KEY>`。
   手动方式（不推荐）：访问 `https://api.telegram.org/bot<你的BOT_TOKEN>/setWebhook?url=https://<你的域名>/`。注意：手动注册不带防伪密钥，机器人会拒绝所有更新（403），需带密钥访问一次 `/health` 重新同步

6. **Cron 触发器（撤回功能依赖，强烈建议配置）**：Worker → 设置 → 触发事件 → Cron 触发器 → 添加 `* * * * *`（每分钟，Cron 最小粒度）。
   作用：每分钟清扫一次到期的撤回任务与过期数据，不依赖消息流量；未配置时仅在有消息往来时触发清扫，空闲期的撤回会延后到下一条消息到达。
   Wrangler 方式则在 `wrangler.toml` 里加：
   ```toml
   [triggers]
   crons = ["* * * * *"]
   ```

### 方式 B：Wrangler 命令行

`wrangler.toml` 参考（完整示例见源码文件头部注释）：

```toml
name = "tg"
main = "worker.js"
compatibility_date = "2024-09-01"

d1_databases = [
  { binding = "DB", database_name = "tg-bot", database_id = "<建库后得到的ID>" }
]

[ai]
binding = "AI"

[vars]
BOT_TOKEN = "123456:AAxxxx..."
SUPERGROUP_ID = "-1001234567890"
TURNSTILE_SITE_KEY = "0x4AAA..."
TURNSTILE_SECRET_KEY = "0x4BBB..."
ADMIN_IDS = "123,456"
AI_MODEL = "@cf/zai-org/glm-4.7-flash"
AI_IMAGE_CHECK = "true"
AI_IMAGE_MODEL = "@cf/meta/llama-4-scout-17b-16e-instruct"
BLOCK_KEYWORDS = "日结|刷单|加微|引流"
```

```bash
npx wrangler d1 create tg-bot        # 建库，把返回的 database_id 填进 toml
npx wrangler deploy                  # 部署（数据表自动创建）
npx wrangler tail                    # 实时日志
```

## 五、命令一览

### 管理员命令（在群组话题内使用；需 ADMIN_IDS 白名单或群管理员身份）

绝大多数管理操作在**资料卡/管理面板按钮**上点击完成（就地执行并刷新卡片）。文本命令仅下表几个；`/reset` `/trust` `/aiwhitelist` `/close` `/open` `/ban` `/unban` 仅按钮可达，无文本命令：

| 命令 | 功能 |
|---|---|
| `/menu`（`/help`、`/start` 同效） | **弹出管理面板并置顶在 General**：用户统计 + 最近 8 位用户列表（点名字直达话题，带 ✅🌟❓🚫⛔ 状态图标）+「🧹 清理失效话题」「🔄 刷新统计」按钮；旧面板自动取消置顶；命令消息随即删除 |
| `/info` | 在用户话题内调出该用户的完整资料卡（带管理按钮），**卡片 120 秒后自动消失**（新用户进话题时的资料卡不受影响、长期保留并置顶）；命令消息本身随即自动删除 |
| `/verify_ttl` `7d/30d/1y/永久` | 设置验证有效期（需带参数，无对应按钮） |
| `/del` | **撤回发给用户的消息**：回复（引用）目标消息发送；只删用户侧副本，群内原消息保留。文本/媒体/贴纸/语音等均可撤回（相册需逐条）；对方发来的原消息受 Telegram 限制无法代删 |

> **资料卡按钮**：🔄 刷新（重新拉取资料/状态）、🔄 重置验证、🌟 信任、🚫 关闭对话、✅ 恢复对话、🤖 AI检测、⛔ 屏蔽此人/✅ 解除屏蔽——点击就地执行并刷新卡片，仅管理员可点。
>
> **管理面板按钮**（`/menu` 弹出）：🧹 清理失效话题（即原 /cleanup）、🔄 刷新统计。

### 用户命令

| 命令 | 功能 |
|---|---|
| `/start` | 欢迎语 + 触发人机验证 |

## 七、数据库说明

三张表，全部**首次访问时自动创建**（`CREATE TABLE IF NOT EXISTS`），每 1 分钟自动清理过期数据：

| 表 | 用途 |
|---|---|
| `users` | 用户主表：一行 = 话题/资料/验证/封禁/拦截计数/验证挑战/AI白名单 |
| `messages` | 双向消息台账：源消息 ↔ 副本映射（编辑同步用）+ AI 对话情景记录 |
| `kv` | 通用临时状态：限速计数、验证挑战暂存、相册缓冲、补发去重、各类缓存与锁 |

> 🧹 清理失效话题 = 整行删除 `users` 并清空其全部 `messages`：对该用户如同从未私聊过，下次发消息需重新验证并新建话题。

## 八、常见问题

| 问题 | 排查 |
|---|---|
| 机器人不回复 | ① 访问 `/health` 看各项是否"配置完成"（同时会自动注册 Webhook，日志看 `webhook_auto_registered`） ② 仍未生效则手动设置 Webhook（见部署第 5 步的手动方式，用后需带密钥访问 `/health` 重新同步） ③ 确认 BotFather 已关闭 Privacy Mode ④ 日志出现 `webhook_secret_missing` / 更新被 403：说明注册时未带防伪密钥，带密钥访问一次 `/health` 同步即可 |
| 新用户收不到验证链接 | Worker 域名是自动记录的：确认至少访问过一次 `/health?key=<密钥>`（首次部署后的首次访问即可完成），再测试；同时确认 Turnstile 的域名配置包含当前 Worker 域名 |
| 命令点了没反应 | 确认操作者是群管理员或已配置 `ADMIN_IDS`；命令需在**绑定了用户的话题**里发。管理操作请优先使用资料卡/面板按钮 |
| AI 全部放行不拦截 | ① `/health` 看 `ai_binding` ② 日志搜 `ai_spam_check_failed`（常见：模型被下线报 5028，换 `AI_MODEL`） ③ 也可直接看 `ai_spam_skipped` 是否出现 |
| 日志报 5028 deprecated | 默认模型被 Cloudflare 下线，换 `AI_MODEL` 为模型目录里的现役模型 |
| 免费额度 | Workers AI 每天 10,000 神经元（约支撑 2000+ 条消息的 AI 审核）；D1 每天 10 万行写入；本项目常规用量完全免费 |
